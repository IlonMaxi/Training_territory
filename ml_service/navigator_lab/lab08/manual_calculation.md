# Ручной расчёт и сверка с кодом

Все примеры ниже посчитаны вручную и повторены тестами класса `ManualCalculationTests` в `tests.py`, чтобы ошибка в подсчёте не спряталась за красивым средним.

**1. feedback на validation.** 5 запросов feedback, baseline ответил feedback 3 раза, все три верно. Precision = 3/3 = 1, recall = 3/5 = 0.6, F1 = 2 * 1 * 0.6 / (1 + 0.6) = 1.2 / 1.6 = 0.75. В коде 0.7500 (`results/validation_per_class.csv`).

**2. workout на validation.** 9 запросов workout, 14 ответов workout, верных 9. Precision = 9/14 = 0.643, recall = 9/9 = 1, F1 = 2 * (9/14) * 1 / (9/14 + 1) = 18/23 = 0.783. В коде 0.7826. Recall 1 не значит, что workout работает хорошо: 5 ответов workout получили запросы других разделов.

**3. Macro-F1 baseline.** Среднее F1 по 12 намерениям: (0.571 + 0 + 0.750 + 0.222 + 0.533 + 0.500 + 0.333 + 0.857 + 0.545 + 0 + 0 + 0.783) / 12 = 5.095 / 12 = 0.425. В коде 0.4246. Отдельный тест сверяет эту величину с `f1_score(average='macro', zero_division=0)` из scikit-learn. Пустой ответ передаётся туда как метка «нет ответа», которой нет в списке намерений.

**4. Маленький пример.** Верные метки: a, a, b, c. Ответы: a, b, b, нет ответа.

- a: precision 1/1, recall 1/2, F1 = 2 * 1 * 0.5 / 1.5 = 0.667
- b: precision 1/2, recall 1/1, F1 = 0.667
- c: ответов нет, F1 = 0
- macro-F1 = (0.667 + 0.667 + 0) / 3 = 4/9 = 0.444; accuracy = 2/4 = 0.5
- ошибочных переходов 1 из 4: на второй запрос a открыт раздел b, то есть 0.25; «нет ответа» переходом не считается

**5. Неверный ответ хуже отказа.** Те же верные метки a, a, b, c.

| Вариант | Ответы | Accuracy | Macro-F1 | Ошибочные переходы |
|---|---|---|---|---|
| Промолчал на c | a, a, b, нет ответа | 0.75 | (1 + 1 + 0) / 3 = 0.667 | 0 |
| Ошибся на c | a, a, b, a | 0.75 | (0.8 + 1 + 0) / 3 = 0.600 | 0.25 |

Во втором варианте у a precision 2/3 и recall 1, поэтому F1 = 2 * (2/3) * 1 / (5/3) = 0.8. Accuracy не различает варианты, а macro-F1 и доля ошибочных переходов ставят молчание выше ошибки. Это и есть причина выбора основной и защитной метрики.

**6. Крайние случаи.** Все ответы верные: macro-F1 = 1. Ответов нет совсем: macro-F1 = 0, accuracy = 0, ошибочных переходов 0. Поэтому доля ошибочных переходов работает только как защитная метрика: навигатор, который молчит, выглядит по ней идеально.

**7. «Прочее» не переход.** Верные метки a, other; ответы other, a. Первый ответ ничего не открывает, второй открыл раздел на посторонний запрос. Ошибочных переходов 1 из 2, то есть 0.5.

**8. Кнопки.** Ближайшие запросы train по убыванию сходства имеют метки chat, chat, other, feedback, trainer, support. Кнопки: chat, feedback, trainer - повтор пропускается, «прочее» не показывается. Для запроса feedback нужная кнопка есть, для support - нет: попадание 1 из 2, то есть 0.5.

**9. Матрица ошибок.** Сумма каждой строки равна числу запросов этого намерения, сумма диагонали - 29 верных ответов, последний столбец - 8 запросов без ответа. Это совпадает с `results/validation_metrics.csv`.
