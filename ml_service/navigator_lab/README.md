# Baseline навигатора (ЛР 7)

Навигатор по короткому запросу в чате определяет, какой раздел платформы нужен пользователю. Намерений 12: workout, schedule, progress, nutrition, chat, trainer, clients, subscription, settings, support, feedback, other. Здесь лежит baseline - простая воспроизводимая точка отсчёта, с которой будут сравниваться улучшения в ЛР 8-9.

Baseline ищет в train самый похожий запрос по TF-IDF словам и берёт его намерение. По train считаются только словарь и IDF, обучаемых весов нет. Это проще любой модели с обучением и легко объясняется: для каждого ответа видно, какой запрос train его дал и по каким словам. Для сравнения посчитан ещё ответ «всегда самый частый класс train» (workout).

## Запуск

Нужен Python 3.10 или новее, сторонние библиотеки не нужны. Команды выполняются из папки `ml_service`:

```powershell
cd ml_service
python -m navigator_lab run
python -m navigator_lab predict --query "цена абонемента" --query "абонемент"
python -m unittest navigator_lab.tests -v
```

`run` проверяет хеш данных, строит словарь и IDF по train, отвечает на 63 запроса validation и записывает файлы в `results`. В конце печатаются хеши файлов: повторный запуск даёт те же значения. Test в этой работе не используется.

`predict` показывает три ближайших запроса train и ответ, метрики не пересчитывает. Для «цена абонемента» ответ subscription (ближайший запрос «срок абонемента»), для «абонемент» ответа нет: в train это слово есть только в форме «абонемента».

Тесты проверяют хеш и размеры выборок, пустой запрос, неизвестные слова, порядок при равных оценках, то, что словарь строится только по train, и совпадение формулы TF-IDF и macro-F1 с scikit-learn. Последняя проверка пропускается, если scikit-learn не установлен.

## Алгоритм

1. Привести текст к нижнему регистру, заменить ё на е.
2. Выделить слова из букв и цифр.
3. Посчитать, сколько раз каждое слово встречается в запросе.
4. Умножить на IDF по train: ln((1 + N) / (1 + df)) + 1, где N - число запросов train, df - число запросов train с этим словом. Слов не из словаря train в векторе нет.
5. Нормировать вектор, после этого скалярное произведение равно косинусному сходству.
6. Посчитать сходство со всеми запросами train и убрать нулевые совпадения.
7. Отсортировать по убыванию сходства, равные оценки - по возрастанию ID.
8. Взять намерение первого запроса. Если совпадений нет, ответа нет, и это считается ошибкой.

## Файлы

| Материал | Где |
|---|---|
| Код baseline | `baseline.py` - модель, `data.py` - загрузка и проверка данных, `metrics.py` - метрики, `__main__.py` - команды, `tests.py` - проверки |
| Данные | `data/intents_clean_v2.csv` из ЛР 6, хеш 60d80a7acb7eb7fa |
| Настройки | `settings.md` |
| Таблица метрик | `results/validation_metrics.csv`, по намерениям `results/validation_per_class.csv` |
| Ответы по каждому запросу | `results/validation_baseline.csv`, вместе с тремя соседями `results/validation_baseline_detail.json` |
| Окружение | `results/environment.json` |
| Удачные и ошибочные случаи | `baseline_findings.md` |

В `validation_baseline.csv` столбец `shared_words` показывает, по каким словам выбран ответ, а `unknown_words` - каких слов нет в словаре train. Столбцы `error_type` и `train_forms` нужны только для разбора ошибок, в модели они не участвуют. `train_forms` для неизвестного слова показывает слова train с теми же первыми пятью буквами, как в правиле групп из ЛР 6.

## Критерии приёмки

| Критерий | Чем подтверждается |
|---|---|
| Baseline запускается повторно | Одна команда `run`; два запуска дают файлы с одинаковыми хешами; тест `test_prediction_is_repeatable` |
| Он проще будущего решения | Нет обучаемых весов, стоп-слов, исправления опечаток и частей слов, сравниваются только целые слова из train |
| Метрики подходят задаче | Классификация по 12 неравным по размеру намерениям, поэтому основная метрика macro-F1, как решено в ЛР 5; пустой ответ считается ошибкой |
| Примеры показывают границы, а не только успех | В `baseline_findings.md` 10 удачных и 10 ошибочных случаев с причинами, все 63 ответа лежат в `results` |
